# Jev フォーム入力（Chrome拡張）

貼り付けた内容を、開いている画面の入力欄へ一括で入れる。Concur経費精算・SAP系勤怠のような
「毎回同じ画面に同じ種類の項目を打つ」作業向け。

**送信・保存ボタンは押さない。** 入力までで止め、確認と提出は本人が行う。

## 入れ方

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパー モード」をオン
3. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダ（`jev-autofill`）を選ぶ
4. ツールバーのアイコン、または **Alt+J** でサイドパネルが開く
5. 初回だけ「設定」に Jev の APIキーを入れて保存

## 使い方

1. サイドパネルに内容を貼る（どれでもよい）
   - JSON（concur-expense-assistant スキルの出力をそのまま。配列なら明細を選べる）
   - `項目: 値` を1行ずつ
   - 自由文（`9/18 新幹線 東京 新大阪 14720円 …`）
2. 「読み取って割り当て」→ 画面の欄に色枠が付き、サイドパネルに割り当て一覧が出る
3. 確認して「入力する」
4. 「この対応を保存」すると、次回からその画面はJevに聞かずに入る

## 割り当ての順番

| 順 | 方法 | 通信 |
|---|---|---|
| 1 | 保存済みの対応表 | なし |
| 2 | 欄のラベルと項目名の文字列一致 | なし |
| 3 | Jev（残った欄だけ、1〜2リクエストにまとめて） | あり |

選択欄は「入力値 → 選んだ項目」も学習する。例: `taxi → タクシー代` を一度覚えれば次回は通信なし。
初めて見る値のときだけ、その欄をJevに聞く。

## 安全策

- パスワード欄、カード番号系（`autocomplete="cc-*"` や name に card number 等）、読み取り専用、非表示の欄は対象外
- `click()` は一切呼ばない。提出・保存は必ず本人
- Jev に送るのは「貼り付けた内容」と「欄のラベル・種類・選択肢」だけ。画面に入っている既存の値は送らない
- 設定で「Jevを使う」をオフにすると、保存済みの対応表と名前一致だけで動く（外部通信なし）
- APIキーは `chrome.storage.local`（このPCのこのChromeだけ）に保存

## 実測（テスト用の模擬画面、2026-09-21）

10欄（select 3・date・textarea・shadow DOM・iframe・React風の制御入力を含む）+ パスワード欄・カード欄・readonly・hidden。

| 入力の形 | 割り当て | Jev |
|---|---|---|
| 英語キーのJSON（初回） | 10/10欄、確信度 93〜100% | 734ms・2リクエスト |
| 同じ画面の2回目（対応表あり） | 10/10欄 | **0ms・通信なし** |
| 別の経費（タクシー） | 9欄 | 221ms（選択欄2つだけ） |
| 日本語の「項目: 値」 | 9/10欄（8欄は名前一致） | 207ms |
| 自由文 | 8/10欄 | 222ms |

入力テスト: 全10欄 `ok`。React風の欄も表示値と内部状態の両方が一致。
パスワード欄・カード欄は空のまま、提出・保存ボタンのクリック数は 0。

## テスト

```bash
node test/serve.mjs          # http://localhost:5188 に模擬画面
node test/plan-e2e.mjs       # 割り当てロジックを本物のJevで試す（jev-benchmark/.env のキーを使う）
```

## 既知の限界

- 実際の Concur / SAP 勤怠の画面では未検証（社内SSOの奥なので）。最初の1回はプレビューを見て確認すること
- 開くと候補一覧が出るタイプの独自コンボボックス（`<select>` ではないもの）は、テキストとして入力する。候補から選び直しが必要な場合がある
- 領収書の添付（ファイル選択）は対象外
